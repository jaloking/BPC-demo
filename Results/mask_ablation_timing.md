# visited 与 cut_parity 四组合消融对比

日期：2026-10-23。四版在同一批实验中重新测量，每版 8 次独立 JVM，使用轮换及反向顺序，平衡先后位置。
JDK 25、CPLEX 20.1、单线程 LP、完整欧氏距离、相同 BPC 参数、每节点默认最多 20 条割。
计时为 Solver.solve() 的墙钟耗时，不含编译、读取实例和写结果；没有额外预热，首例含 JVM/CPLEX 初始化影响。
主项目仍使用双 int 版本；仅 cut_parity int 是独立的实验版本。

| 版本 | visited | cut_parity |
| --- | --- | --- |
| boolean_array | boolean[] | boolean[] |
| visited_int | int | boolean[] |
| cut_parity_int | boolean[] | int |
| both_int | int | int |

## 单独修改的效果

| 实例 | 仅 visited 相对原版耗时变化 | 仅 cut_parity 相对原版耗时变化 | 仅 cut_parity 相对仅 visited耗时变化 |
| --- | ---: | ---: | ---: |
| C101_25 | -15.06% | -3.18% | +13.99% |
| R101_25 | -1.55% | -2.68% | -1.14% |
| RC101_25 | -2.04% | -21.54% | -19.91% |

负百分比表示更快，正百分比表示更慢。全部 96 条原始算例计时记录见 mask_ablation_timing.csv。
四版所有运行的最优值、车辆数和搜索节点数一致。新增的仅 cut_parity int 版本通过 495 项回归检查及 10,000 次割状态比较和边界测试。
本表是本批次测量，不能直接与旧批次的绝对时间比较；小耗时受到 JIT、GC、操作系统调度等影响，不保证差异可推广。
即使无活跃割，原 Label 仍初始化并复制长度为零的布尔数组；将 cut_parity 改为基本类型会同时移除这些数组操作。
因此无割实例也可能变化，但当前只测总求解时间，不能据此断定各内部步骤的占比。
